# pi-agent-hub

Хаб для кодинг-агентов на [pi-durable](https://github.com/earendil-works/pi/tree/main/packages/durable). У каждого агента свой Docker-контейнер и своя папка проекта. Люди подключаются через веб-страницу или HTTP API и работают с агентами одновременно. Если убить процесс хаба, после перезапуска агенты продолжат с того места, где остановились.

## Запуск

```bash
npm install
npm start                                  # демо-модель, без ключа
ANTHROPIC_API_KEY=sk-ant-... npm start     # Claude Sonnet 5.5
```

Откройте http://127.0.0.1:8787, укажите своё имя, создайте агента.

Демо-модель нужна, чтобы проверить механику бесплатно. Сообщение, начинающееся с `$`, выполняется как команда в контейнере агента. Остальное модель просто повторяет.

Нужны Node.js 22.19+ и Docker. Пользователь, от которого запущен хаб, должен иметь доступ к `docker`.

## Настройки

| Переменная | По умолчанию | |
|---|---|---|
| `HOST`, `PORT` | `127.0.0.1`, `8787` | Наружу — `HOST=0.0.0.0`, но только вместе с `HUB_TOKEN` |
| `HUB_TOKEN` | пусто | Общий токен доступа к API и странице |
| `MODEL` | `anthropic/claude-sonnet-5-5` при наличии ключа, иначе `faux/demo` | |
| `DATA_DIR` | `./data` | `agents.sqlite` и `projects/<slug>/` |
| `AGENT_IMAGE` | `ubuntu:24.04` | Образ контейнеров. Для реальной работы соберите свой, с git, node, python |
| `AGENT_MEMORY`, `AGENT_CPUS`, `AGENT_PIDS` | `2g`, `2`, `512` | Лимиты на контейнер |
| `AGENT_NETWORK` | `bridge` | `none`, если агентам не нужен интернет |

## Как устроено

```
браузер ──HTTP/SSE──▶ src/server.ts ──▶ Harness (pi-durable) ──▶ data/agents.sqlite
                                            │
                                            └─ env() ──docker exec -i──▶ pi-agent-<slug>
                                                                          └─ pi-env daemon → bash/read/write/edit
                                                                             /workspace = data/projects/<slug>
```

- Один агент — это одна беседа pi-durable. Все беседы лежат в одной SQLite-базе, планировщик ведёт их параллельно.
- Инструменты агента никогда не выполняются на хосте. Демон `pi-env` смонтирован в контейнер и запускается через `docker exec`. Агент видит только `/workspace`, переменные окружения хаба (ключи API) в контейнер не попадают. Контейнер работает без capabilities и от uid пользователя хаба, поэтому файлы проекта на хосте остаются вашими.
- Каждое сообщение, ответ модели и вызов инструмента сначала записывается в базу, а уже потом показывается. После падения процесса `harness.resume()` продолжает незавершённую работу:
  - запрос к модели повторяется;
  - прерванный `bash` не перезапускается вслепую: агент получает уже записанный вывод и пометку «interrupted» и сам решает, что делать;
  - сообщения из очереди не теряются.
- Если несколько человек пишут одному агенту, сообщения встают в очередь, а флажок «вмешаться» подмешивает сообщение в текущую работу (`whenBusy: "steer"`). Модель видит каждое сообщение с именем автора.

## API

| | |
|---|---|
| `GET /api/agents` | список агентов: `busy`, контейнер |
| `POST /api/agents` `{name}` | создать агента (беседа + контейнер) |
| `POST /api/agents/:id/messages` `{author, text, requestId?, mode?: "steer"}` | написать агенту. Повтор с тем же `requestId` не создаёт дубль |
| `GET /api/agents/:id/events` | SSE: сначала снимок состояния, потом события (`watchEvents`) |
| `POST /api/agents/:id/abort` | остановить текущую работу, очередь сбрасывается |

С `HUB_TOKEN` передавайте заголовок `Authorization: Bearer <токен>` или параметр `?token=`.

## Проверить переживание падений

1. Напишите агенту `$ for i in $(seq 1 30); do echo $i; sleep 1; done`.
2. Пока команда идёт, выполните `pkill -9 -f src/server.ts`, затем снова `npm start`.
3. Страница переподключится сама. В транскрипте будет вывод до момента падения и ответ агента на прерванную команду.

## Чего здесь нет

- **Пользователей и прав.** Есть только общий токен. Кто к какому агенту имеет доступ, нужно добавлять в `src/server.ts`.
- **Изоляция ограничена контейнером, а не VM.** Сам хаб имеет доступ к Docker, это равносильно root на хосте, поэтому держите его на отдельной машине. Сеть в контейнерах по умолчанию открыта.
- **Масштабирования.** Одну базу может держать только один процесс. Падение процесса останавливает всех агентов до перезапуска, поэтому держите хаб под systemd или docker с `restart: always`.
- **Удаления агентов.** Контейнер `pi-agent-<slug>` и папка `data/projects/<slug>` удаляются вручную.
- **Стабильного API движка.** pi-durable экспериментальный, версии в `package.json` зафиксированы точно. Обновляйтесь осознанно и запускайте `npm run check`.
